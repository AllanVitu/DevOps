Langages

JavaScript (modules ES), HTML et CSS, écrits sous forme de composants Vue monofichiers compilés par Vite. Le dépôt ne contient que le résultat de la compilation (docs/), pas les sources.

Architecture

docs/
├── index.html            thème appliqué avant le rendu (pas de flash)
├── manifest.webmanifest  PWA installable
├── sw.js                 service worker (cache devtoolbox-v2)
└── assets/               ~130 fichiers produits par Vite
    ├── index-*.js        noyau : routeur, registre des outils, leçons (198 Ko)
    ├── index-*.js        SDK Anthropic, chargé à la demande (164 Ko)
    ├── JsonFormatter-*.js, JwtDecoder-*.js, …   un fichier par outil
    └── use*.js           composables partagés

Chaque outil est déclaré dans un registre (id, nom, catégorie, mots-clés, accepts, composant). Les champs keywords alimentent la palette de recherche ; accepts dit quels types de données l'outil sait recevoir d'un autre outil.

  • Pipeline (usePipeline) — un outil dépose son résultat, l'outil cible le consomme s'il accepte ce type.
  • Partage (useShareLink) — la saisie est sérialisée en JSON puis en Base64 URL-safe dans le paramètre ?d=.
  • IA (useClaude, useToolAI) — streaming, arrêt en cours de réponse, erreurs de clé et de débit traduites.

Sécurité. La clé API est conservée dans le localStorage du navigateur et envoyée directement à l'API Anthropic. L'application le signale : le chat est la seule fonction qui n'est pas hors-ligne.

3. serveur — BoxCraft

Resource pack du serveur Minecraft BoxCraft — « PvP / Survie / Quêtes ».

Langages

JSON pour toutes les définitions (métadonnées du pack, objets, modèles, équipement, police) et PNG pour les textures. Le pack est livré sous forme d'archive BoxCraft_ResourcePack.zip (25 Ko).

Technologies

  • Resource pack Minecraft Java, format de pack 88 (min_format / max_format dans pack.mcmeta), passage au format 26.2 le 14/08/2026.
  • Définitions d'objets (assets/boxcraft/items/) : chaque objet pointe vers son modèle ; le serveur l'attribue via les composants d'objet, sans écraser d'objet du jeu de base.
  • Modèles (assets/boxcraft/models/item/) : éléments cubiques texturés et transformations d'affichage (main, sol, inventaire, cadre, tête).
  • Équipement (assets/boxcraft/equipment/emeraude.json) : texture de l'armure portée.
  • Police (assets/minecraft/font/default.json) : fournisseur bitmap pour le logo.

5. Procédés d'évolution

Comment les projets avancent aujourd'hui

  • Itérations courtes : chaque dépôt a été construit en une à deux semaines, un commit par fonctionnalité visible (un outil, une leçon, un objet).
  • Déploiement statique : DevToolbox est compilé en local puis publié par GitHub Pages depuis docs/. BoxCraft est publié sous forme de ZIP.
  • Hors-ligne d'abord : les fonctions qui dépendent du réseau (l'IA) sont isolées, chargées à la demande et signalées.

Limites constatées

  • Sources absentes (DevToolsBox) — seul le build est versionné. Chaque modification régénère des fichiers aux noms hashés : les commits touchent 48 à 132 fichiers et l'historique ne montre pas ce qui a changé dans le code.
  • Langage non détecté — GitHub n'affiche aucun langage pour les trois dépôts : DevToolsBox ne contient que docs/, classé comme documentation ; serveur ne contient qu'un ZIP binaire ; App est vide.
  • ZIP binaire (serveur) — les 6 commits de contenu ne remplacent qu'un seul fichier binaire : impossible de voir quel modèle ou quelle texture a changé.
  • README vides — une ligne par dépôt, sans instructions d'installation ni capture.
